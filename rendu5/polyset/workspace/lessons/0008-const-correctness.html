Const-correctness

Objetivo: leer const tras la firma de un método como parte del contrato, no decoración — y conectar por qué obliga a usar node* en vez de node** cuando solo lees.

La sintaxis, por piezas

bool has(int val) const {
Fragmento Significa
bool has(int val)Firma normal del método.
const (tras los paréntesis)Parte de la firma, no cosmética: "este método promete no modificar ningún miembro del objeto". Cambia el tipo de this.

Modelo mental (no es sintaxis válida para escribir, pero así se comporta): un método const recibe implícitamente const Clase* this en vez de Clase* this. Por eso dentro no puedes reasignar miembros ni llamar a métodos no-const sobre this.

Por qué has() usa node* y no node**

Ya lo razonaste tú mismo, conectándolo con el Bloque 2. Compara las dos funciones:

tree_bag::insert()
(no const)
Usa node** current = &tree;. Necesita la dirección modificable de un puntero del árbol (tree, left o right) para poder reasignarlo: *current = new node(val); cambia el árbol de verdad.
searchable_tree_bag::has()
(const)
Usa node* current = this->tree;. Solo avanza una copia local del puntero (current = current->l;) — no reasigna ningún enlace del árbol real. Con this constante, ni siquiera podrías tomar &this->tree para modificarlo.

Objeto const → solo métodos const

Ya lo usas en tu propio main.cpp:

05/level-1/polyset/main.cpp 
const searchable_array_bag tmp(static_cast<searchable_array_bag &>(*a));
tmp.print();   // compila: print() es const
tmp.has(1);    // compila: has() es const
// tmp.insert(42);  // NO compilaría: insert() no es const
Caso resuelto — checkpoint

Pregunta: ¿por qué insert() usa node** y has() solo node*? ¿Qué tiene que ver const?

Tu respuesta: insert() necesita modificar a qué apunta un puntero del árbol (requiere su dirección, de ahí el doble puntero). has(), siendo const, solo lee — avanza una copia local del puntero sin tocar el árbol real. Modelaste correctamente this como const Clase* dentro del método.
