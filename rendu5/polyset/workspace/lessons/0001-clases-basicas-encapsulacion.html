Clases básicas y encapsulación

Objetivo de esta lección: entender public / protected / private lo bastante bien como para justificar, con el código real de array_bag, por qué un dato vive en una banda de acceso y no en otra.

Qué es una clase

Una class agrupa datos (variables miembro) y funciones que operan sobre esos datos (métodos), con control de quién puede tocar qué. En C puro tenías struct — solo datos — y funciones sueltas que la recibían como parámetro: nada impedía que cualquier función tocara cualquier campo. C++ añade la posibilidad de esconder el estado interno y solo dejarlo tocar a través de un contrato controlado. Eso es encapsulación.

class es privada por defecto; struct es pública por defecto — esa es la única diferencia real entre ambas palabras clave en C++. Los métodos se declaran en el .hpp y se implementan en el .cpp con ::, el operador de resolución de ámbito: array_bag::array_bag() se lee "el constructor de la clase array_bag".

El corte transversal de acceso

Encapsulación no es una única puerta cerrada — son tres bandas concéntricas, cada una con una regla de visibilidad distinta:

public
Visible desde cualquier sitio: la propia clase, sus hijas, y código externo. Es el contrato — lo único que quien usa la clase necesita conocer.
protected
Visible para la clase y para quien hereda de ella. Cerrado para el resto del mundo. Es la banda que usa array_bag para data y size.
private
Visible solo dentro de la propia clase — ni siquiera las clases hijas pueden tocarlo directamente. El nivel por defecto de class.

Cómo aparece en tu código

bag.hpp todavía no tiene datos — es un contrato puro (volveremos a esto en el Bloque 5, clases abstractas). Donde sí hay estado real es en array_bag:

05/level-1/polyset/array_bag.hpp 
class array_bag : virtual public bag
{
 protected:
    int *data;
    int size;

 public:
    array_bag();
    array_bag(const array_bag &);
    array_bag &operator=(const array_bag &other);
    ~array_bag();
    ...
};

Y el motivo concreto de por qué protected y no private está en la clase hija, no en array_bag mismo:

rendu5/polyset/searchable_array_bag.cpp 
bool searchable_array_bag::has(int val) const {
    for (int i = 0; i < this->size; i++) {
        if (this->data[i] == val)
            return true;
    }
    return false;
}

has() está definida en searchable_array_bag — la clase hija — y lee this->data y this->size directamente, sin pasar por ningún getter. Si esos dos campos fueran private en array_bag, esta función ni siquiera compilaría.
