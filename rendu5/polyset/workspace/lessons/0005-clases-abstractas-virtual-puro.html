Clases abstractas y funciones virtuales puras

Objetivo: leer virtual ... = 0, entender para qué sirve una clase abstracta, y saber que la "abstractidad" se propaga hasta que alguien implementa todas las funciones puras.

La sintaxis, por piezas

virtual void insert (int) = 0;
Fragmento Significa
virtualLa llamada se resuelve en runtime según el tipo real del objeto, no en compilación según el tipo del puntero.
void insert(int)Firma normal: nombre, parámetros, retorno.
= 0Pure specifier — no hay cuerpo aquí. No es una asignación ni un valor.

Por qué existe: un contrato común

Sin clase abstracta, el código que usa un bag tendría que conocer cada tipo concreto por separado. Con ella, cualquier código puede tratar "algo que es un searchable_bag" sin saber si por dentro hay un array o un árbol — ya lo estás haciendo en tu propio main.cpp:

05/level-1/polyset/main.cpp 
searchable_bag *t = new searchable_tree_bag;
searchable_bag *a = new searchable_array_bag;
...
t->has(atoi(argv[i]));   // no sabe ni le importa qué hay por dentro
a->has(atoi(argv[i]));   // mismo código, dos implementaciones distintas

Eso es lo que vas a formalizar en el Bloque 7 (polimorfismo). Y en el Bloque 9, set está escrito enteramente contra searchable_bag& — no necesita saber qué bag concreto envuelve.

La abstractidad se propaga

Una clase es abstracta si define o hereda al menos una función virtual pura sin implementación final. No basta con implementar 3 de 4 — con que quede una sola pendiente, la clase entera sigue siendo abstracta.

bag
4 funciones = 0, ninguna implementada. Abstracta. bag b; no compila.
array_bag
(hipotético, sin clear())
Implementa 3 de 4. clear() sigue siendo = 0, heredada tal cual. Sigue abstracta. array_bag a; tampoco compilaría.
clase que implementa
las 4 (tu array_bag real)
Ninguna función pura queda sin cuerpo. Concreta. array_bag a; compila.

Punteros y referencias al tipo abstracto sí son válidos incluso cuando no lo es la instanciación directa: array_bag* p; compila siempre — declarar un puntero no crea un objeto.

Caso resuelto — checkpoint

Pregunta: si array_bag no implementara clear(), ¿seguiría siendo abstracta? ¿Compilaría array_bag a;?

Tu respuesta: seguiría abstracta — basta una función pura sin implementar, da igual que el resto estén bien. array_bag a; no compilaría, pero array_bag* p; sí. Una clase más derivada que implemente clear() podría volver a ser concreta.
