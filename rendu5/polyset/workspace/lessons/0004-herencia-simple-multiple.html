Herencia simple y múltiple

Objetivo: leer con soltura la lista de inicialización (: array_bag(other)) y saber qué falla si no reenvías el argumento a la clase base.

searchable_array_bag es dos cosas a la vez

class searchable_array_bag : public array_bag, public searchable_bag hereda de dos clases simultáneamente — no reemplaza nada, combina: se queda con data/size/insert/print/clear de array_bag (implementación) y cumple el contrato has() de searchable_bag (interfaz). Por eso su private: está vacío — no necesita datos propios, ya los tiene por herencia.

El contrato has(int) const = 0 — searchable_array_bag lo cumple con su propia implementación (búsqueda lineal sobre la parte array_bag).

La lista de inicialización — léela por trozos

Antes de ejecutar el cuerpo {} del constructor de la clase hija, C++ tiene que construir sus subobjetos base. Eso es lo que controla la sintaxis tras : — se llama lista de inicialización de miembros y bases, no std::initializer_list (son cosas distintas con nombre parecido).

Fragmento Significa

{}Cuerpo del constructor de la hija — vacío, no hace falta nada más.

Orden real de construcción: 1) bases virtuales, 2) bases directas (izquierda a derecha), 3) miembros no estáticos (orden de declaración), 4) cuerpo del constructor.

Dónde importa de verdad: el constructor de copia

: array_bag()
(el bug)
Llama al constructor por defecto de array_bag, no al de copia. other queda ahí, sin usarse. El objeto nuevo se construye sin error de compilación — pero con data = NULL, size = 0: un "constructor de copia" que no copia.
: array_bag(other)
(lo real)
Reenvía other al constructor de copia de array_bag, que reserva memoria nueva y copia cada entero (Bloque 2). El objeto nuevo tiene su propio data, con los valores de other.

other es const searchable_array_bag&, pero puede pasarse donde se espera un const array_bag& — un searchable_array_bag es también, públicamente, un array_bag.

Regla práctica para el examen

Lee cualquier constructor derivado así: 

Hija::Hija(argumentos) : Base(argumentos_para_Base) {
    // código adicional de Hija
}

→ "Antes de entrar en las llaves, construye la parte Base llamando a este constructor concreto." Las bases se inicializan antes de que se ejecute el cuerpo del constructor derivado, siempre.

Caso resuelto — checkpoint

Pregunta: ¿qué falla si el constructor de copia usa : array_bag() en vez de : array_bag(other)?

Tu respuesta: no hay error de compilación; el objeto se construye correctamente pero queda vacío — data = NULL, size = 0 — en vez de ser una copia de other. El parámetro está ahí pero no se usa.
