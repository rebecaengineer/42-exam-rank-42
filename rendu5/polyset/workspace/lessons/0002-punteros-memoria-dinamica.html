Punteros y memoria dinámica

Objetivo: entender por qué el constructor de copia de array_bag hace una copia profunda del array, y qué crash concreto provoca no hacerlo.

new[] / delete[] — el par obligatorio

En C ya usabas malloc/free (Libft, get_next_line). En C++, array_bag usa su equivalente: new int[size] reserva un array en el heap, delete[] data lo libera. Misma idea, sintaxis distinta — y, como malloc/free, cada new[] necesita exactamente un delete[], ni cero ni dos.

Copia superficial vs. copia profunda

El bug no está en new/delete en sí — está en qué hace el constructor de copia con el puntero data que ya existe en src.

shallow copy
(el bug)
data = src.data; — copia la dirección, no el contenido. src y la copia terminan compartiendo el mismo array. Ninguno sabe que el otro existe.
deep copy
(lo real)
data = new int[size] + bucle que copia elemento a elemento. Cada objeto tiene su propio array — nada compartido, nada que pisarse.

Cómo aparece en tu código

05/level-1/polyset/array_bag.cpp 
array_bag::array_bag(const array_bag &src) {
    size = src.size;
    data = new int[size];
    for (int i = 0; i < size; i++) {
        data[i] = src.data[i];
    }
}

Y el motivo de por qué esto es obligatorio está en el destructor, no en el constructor de copia:

05/level-1/polyset/array_bag.cpp 
array_bag::~array_bag() {
    if (data != NULL) {
        delete[] data;
        data = NULL;
    }
}

Si src y la copia comparten data, cuando el primer objeto se destruye libera esa memoria. Cuando el segundo se destruye —en cualquier orden— delete[] se ejecuta otra vez sobre la misma dirección ya liberada: double free, comportamiento indefinido, típicamente un crash o corrupción del heap.

Caso resuelto — checkpoint

Pregunta: ¿qué fallo concreto provocaría data = src.data; en vez de la copia profunda?

Primera aproximación: "apuntaría al espacio de memoria... si algo modifica ese espacio, data también se modificaría" — correcto en espíritu (aliasing, estado compartido), pero no era el fallo concreto que pedía la pregunta.

Tras la pista (mirar ~array_bag()): "intentarías borrar dos veces el mismo espacio de memoria al que llamas desde 2 punteros" — exacto. Double free. Bloque 2 confirmado.

Fuente primaria: cppreference — Rule of three. Código real: 05/level-1/polyset/array_bag.cpp (este repo).
