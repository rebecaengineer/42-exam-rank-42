42-tutor/polyset/lección 0003

Forma canónica ortodoxa

Objetivo: entender por qué operator= necesita dos guardas independientes, y por qué 42 exige un constructor por defecto además del Rule of Three.

Qué es

Término de James Coplien (Advanced C++: Programming Styles and Idioms, 1992): toda clase que gestiona un recurso implementa, como unidad, cuatro miembros — constructor por defecto, constructor de copia, operator= y destructor. El Rule of Three de C++ solo exige los últimos tres (gestión de recursos); 42 añade el constructor por defecto por una razón distinta: sin él no puedes declarar arrays ni contenedores de esa clase — el compilador necesita poder construir un elemento sin argumentos.

operator=: dos guardas independientes

Ya dominas el constructor de copia y el destructor (Bloque 2). Lo nuevo de este bloque son las dos trampas de operator= — cada una protege contra un fallo distinto.

05/level-1/polyset/array_bag.cpp 
array_bag &array_bag::operator=(const array_bag &src) {
    if (this != &src) {
        if (data != NULL) {
            delete[] data;
            data = NULL;
        }
        size = src.size;
        data = new int[size];
        for (int i = 0; i < size; i++) {
            data[i] = src.data[i];
        }
    }
    return *this;
}
sin guarda de
autoasignación
a = a; → this == &src. delete[] data destruye el origen antes de copiarlo — src.data queda apuntando a memoria liberada. El bucle final copia valores sin inicializar (UB), no los originales: se pierden.
sin liberar
el dato viejo
a = b; (objetos distintos). data = new int[size] sobreescribe el puntero de a sin haber liberado el array anterior — nadie conserva esa dirección. Memory leak: no crashea, se acumula con cada asignación.

Por qué el constructor por defecto no es sobre memoria

A diferencia de las dos trampas anteriores, esto no es gestión de recursos — es instanciabilidad. array_bag arr[10]; o construir un std::vector<array_bag> necesitan poder crear un elemento sin pasarle argumentos. Sin constructor por defecto, esas declaraciones ni compilan.

Caso resuelto — checkpoints

Autoasignación: trazaste delete[] → data = NULL → new[] → bucle, línea a línea, incluyendo que leer los int sin inicializar es UB. Sin pistas.

Fuga de memoria: identificaste que sobreescribir data sin liberar el array anterior pierde esa dirección para siempre, y que el destructor solo libera el último array. Sin pistas.
