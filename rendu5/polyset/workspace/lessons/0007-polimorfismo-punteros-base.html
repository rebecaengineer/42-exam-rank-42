Polimorfismo con punteros a clase base

Objetivo: distinguir tipo estático vs. dinámico, y entender por qué destruir un objeto derivado a través de un puntero base sin destructor virtual es UB, no "solo un leak".

Tipo estático vs. tipo dinámico

Ya lo usas en tu propio main.cpp, aunque no lo hubiéramos nombrado hasta ahora:

05/level-1/polyset/main.cpp 
searchable_bag *t = new searchable_tree_bag;
searchable_bag *a = new searchable_array_bag;
t->has(atoi(argv[i]));

t tiene tipo estático searchable_bag* (lo que declaraste) pero tipo dinámico searchable_tree_bag (lo que realmente hay en memoria). Como has() es virtual (Bloque 5), la llamada se resuelve en runtime según el tipo dinámico.

El mismo mecanismo, pero al destruir

bag.hpp y searchable_bag.hpp no declaran destructor — C++ genera uno implícito, no virtual. Eso importa en el momento de destruir un objeto a través de un puntero base.

destructor NO virtual
(estado actual de bag)
delete t; con t de tipo searchable_bag* apuntando a un searchable_tree_bag real: comportamiento indefinido. No es "se ejecuta solo el destructor base" de forma garantizada — eso es el resultado frecuente en la práctica, pero el estándar no lo promete. La cadena ~searchable_array_bag() → ~array_bag() → delete[] data puede no arrancar en absoluto: fuga del array, o peor.
destructor virtual
(el arreglo)
virtual ~bag() {} en la base. Al ser virtual, la propiedad se hereda — no hace falta redeclararlo en cada hija (aunque hacerlo explícito no molesta). delete t; ahora dispara la cadena completa desde el tipo dinámico real hasta ~array_bag(), que sí libera data.

Regla de oro

Si una clase tiene al menos una función virtual y se va a usar a través de punteros o referencias base (polimórficamente), su destructor debe ser virtual. Es un caso especial: aquí virtual no es sobre dispatch de comportamiento (Bloque 5) sino sobre garantizar que la cadena de destrucción completa se ejecute.

Caso resuelto — checkpoint

Pregunta: si se añadiera delete t; delete a; a main.cpp, ¿qué destructores se ejecutan? ¿Se libera data correctamente?

Tu respuesta: comportamiento indefinido, no una garantía de "solo el destructor base". La liberación de data no está garantizada — fuga en el caso común, potencialmente peor. Propusiste correctamente virtual ~bag() como arreglo, notando que la virtualidad se hereda.

Distinción entre UB y resultado práctico frecuente — la parte que la mayoría se salta. Bloque 7 confirmado.
