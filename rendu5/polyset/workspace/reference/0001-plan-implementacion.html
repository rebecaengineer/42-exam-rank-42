Plan de implementación — Polyset

Cheat sheet para releer bajo presión de examen: cómo leer cualquier subject de 42 y sacar un orden de construcción — aplicado aquí a Polyset como ejemplo ya resuelto.

1. Contrato del subject

Expected filessearchable_array_bag, searchable_tree_bag, set (.hpp/.cpp)
Allowed functionsninguna restricción especial — solo POO/C++
Restricción explícita"orthodox canonical form. Don't forget the const" — literal del subject

2. Dado vs. pedido

Dado por 42
(no tocar)
bag.hpp, searchable_bag.hpp, array_bag.{hpp,cpp}, tree_bag.{hpp,cpp}, main.cpp
A implementar
searchable_array_bag, searchable_tree_bag (First Part) · set (Second Part)

3. Grafo de dependencias de compilación

[Dados — ya compilan]
bag.hpp ──┬── array_bag.hpp/.cpp
          └── searchable_bag.hpp
tree_bag.hpp/.cpp
        │
        ▼
[First Part — independientes entre sí]
searchable_array_bag : public array_bag, public searchable_bag
searchable_tree_bag  : public tree_bag,  public searchable_bag
        │
        ▼
[Second Part — necesita al menos una de arriba para probarse]
set : compone searchable_bag&  (NO hereda — Bloque 9)
        │
        ▼
[main.cpp usa las TRES a la vez — no compila hasta que existan todas]

4. Orden recomendado y por qué

  1. searchable_array_bag — mismo patrón que array_bag (Bloques 1-3), menor superficie nueva.
  2. searchable_tree_bag — mismo esqueleto; has() recorre el árbol con node*, no node** (Bloque 8).
  3. set — "Second Part" explícita; necesita algo real que envolver para probarse.
  4. main.cpp + grademe/test.sh — incluye build con -fsanitize=address,undefined: pilla un double free (Bloque 2/3) que a simple vista no se ve.

5. Por cada clase

Contrato (qué exige la abstracta) → esqueleto (firmas vacías, que compile) → implementación mínima → verificar:

g++ -std=c++98 -Wall -Wextra -Werror -c searchable_array_bag.cpp

Flags reales de grademe/test.sh de este repo — no inventados. No esperar a tener las tres clases para pillar errores de sintaxis/tipos.

Plantilla para un subject nuevo (examen)

El mismo proceso, en cualquier ejercicio que no hayas visto:

  1. Expected files / allowed functions / qué está dado vs. qué se pide / restricciones explícitas.
  2. Tabla dado vs. pedido.
  3. Grafo: qué necesita existir para que lo siguiente compile/enlace.
  4. Orden: lo más simple o lo que ya dominas primero; lo que depende de más cosas, al final.
  5. Por pieza: contrato → esqueleto → implementación → compilar suelto antes de integrar.
